# EMS · App Store and ConnectX revision (historical)

> **Historical snapshot:** this document describes the pre-direct Connect App/Control relay architecture. For the current EMS-owned SMS queue and direct Android delivery, use [CONNECT_APP.md](CONNECT_APP.md), [CONNECTX_SMS.md](CONNECTX_SMS.md), and the shared `MIGRATION_DEPLOYMENT.md`. Do not use the old endpoint/pairing instructions below.

## What changed

- **Administrator:** removed the ConnectX navigation/page, its shop-setting PATCH/overview and read-only ConnectX usage controls on the Stores page. Plan/add-on entitlements and the Owner’s central Brevo/Connect App credentials remain intact. The App Store now uses the same storefront as the public page.
- **Shop ConnectX:** Email Settings retain the shop-specific on/off switch, sender/reply-to and license-capped daily quota. Attachment HTML template editing and template writes are removed. Previously saved custom document HTML is ignored; actual invoice/receipt/return documents can still be selected and emailed using the fixed safe renderer. SMS Settings retain their message templates and automatic triggers and include **Enable SMS for this shop**. A shop user with Settings edit permission can switch SMS on/off; the server blocks sending when disabled. Partial template edits preserve other saved templates; invalid values and failed settings reads never silently fall back to defaults. Enabled transaction events use the saved shop templates and enqueue only when there is an active ConnectX plan and daily capacity. The Owner still manages the central gateway, and plan expiry/quotas remain enforced.
- **Public/admin App Store:** integrated into the existing public/console page chrome, with no App Store-specific header, footer or theme switch; appearance inherits public, administrator or Owner EMS colors (including their dark themes). Its content is based on the supplied `App store.html`: gradient hero with one search field inside it, real featured rail, category filters, responsive cards, EMS theme-inheriting details sheet (close/backdrop/Escape/focus return). Details include only actual configured screenshots, metadata and authorized installation links. The built-in Mobile Scanner PWA has its own installation QR inside its detail sheet, distinct from its secure PC sign-in QR. Unavailable APKs have no fake download. No sample apps, guessed download counts, invented APK sizes, or placeholder links are published.
- **Supershop SMS:** sale, customer return, actual refund and exchange operations now enqueue corresponding template-based events after the underlying invoice or operation commits. Retries use stable event-specific idempotency keys. Purchases and supplier returns do not send customer SMS. Other existing Electronics/Clothing/Pharmacy transaction hooks are preserved.
- **Overdue reminders:** ConnectX → SMS Gateway → Settings offers an explicit **Queue overdue reminders** action for earlier-dated, outstanding sales. The saved due-reminder template and opt-in switch apply; messages are idempotent by invoice and day. **No scheduled background job is configured**, so the toggle alone does not send reminders. History shows actual queue/delivery state, not a promise of delivery.
- **Owner App Store:** uses compact release rows and featured shortcuts, category/search controls and a live storefront-preview tab with the same detail sheet. The existing signed-APK/icon upload, build code, publish/hide, mandatory update, release notes, delete and refresh flows remain. App editing now supports category, developer, featured flag, optional HTTPS/EMS web app URL and up to six optional screenshot image URLs. External web/screenshot links are validated; APK publication still verifies a real downloadable release. Existing app metadata defaults to `EMS applications` / `Dexter Studio` and not fabricated statistics.

## Database upgrade **before using new App Store metadata**

- **Existing Supabase PostgreSQL:** apply `supabase/migrations/065_app_store_presentation.sql` once after earlier EMS migrations, including 064 if not already applied. Migration 064 is still needed for the shop Email Settings save flow; its new schema no longer contains document HTML templates.
- **Existing Cloudflare D1:** apply `supabase/d1/migration_app_store_presentation.sql` once to an existing App Store schema. Apply `supabase/d1/migration_connectx_shop_email_settings.sql` separately if the shop email table has not been installed. Follow the D1 README for earlier dependencies. **Do not replay migrations on fresh databases created from the complete baseline.** Fresh PostgreSQL and D1 complete baselines include App Store metadata, the lean email settings table and SMS event/idempotency/Connect App columns. Existing D1 databases also need `migration_connectx_gateway.sql` and `migration_connect_app.sql` where not already applied; existing PostgreSQL databases need migrations 041 and 046. Do not replay these migrations on fresh databases.
- The 065/D1 presentation upgrade adds columns and defaults without deleting any existing APK or changing the published-only download/check-update authorization. A previously installed email settings table with a historical `templates` column can stay as-is: the new code never reads or writes it.

## Latest fixes

- Removed the App Store’s duplicate heading/subheading and put a single, clean search input inside its hero. The Owner release manager has a compact, filterable list; all publishing, APK download, preview, update and delete controls remain.
- SMS Compose now previews saved shop templates upon invoice selection instead of generating hard-coded sale text. It also fills the matching shop recipient/phone, includes invoice-level taxes and discounts, filters due reminders to unpaid sales, and never substitutes another customer’s invoice.
- Removed unused shop-facing SMS queue/status mutation routes and retired device-table driver configuration. SMS document/recipient IDs are tenant-checked and a pending message is not deleted after an unconfirmed remote cancellation.
