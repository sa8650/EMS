# Legacy Supabase upgrade migrations

These incremental migrations are retained to preserve upgrade history for existing Supabase deployments. They are not the new-database baseline. New databases should use `supabase/baseline/001_ems_complete_schema.sql` instead of replaying this migration chain.

For an existing database, apply only migration(s) that have not already been applied; do not run a consolidated baseline on top of live data. The Pharmacy upgrade follows CShop: apply `047_clothing_business_console.sql`, `048_pharmacy_console.sql`, `049_pharmacy_return_intake.sql`, `050_pharmacy_sealed_restock.sql`, and `051_pharmacy_aggregate_stock.sql` once and in order. Migration `051` is additive/backward-compatible: it keeps batch and return history, adds/backfills weighted-average base cost, and switches future Pharmacy receipts/sales to aggregate stock. Customer returns stay quarantined with no stock restock or settlement change.

For an **existing** Supabase Pharmacy database, apply `057_pharmacy_catalog_details.sql` after `056_pharmacy_product_delete.sql` (and the earlier Pharmacy migrations) before deploying the updated code. It adds pack size and wholesale price, backfills the manufacturer directory from existing products, and allows clearing an optional Rack / Shelf label. Aggregate stock accounting remains unchanged. Fresh databases use the updated complete baseline instead.

For the **Owner Pharmacy Settings** release on an existing Supabase database, apply `058_pharmacy_owner_catalog.sql` **after** `057_pharmacy_catalog_details.sql`, then deploy the updated application. This creates global master templates and global manufacturers; it does not backfill or overwrite shop medicines. The Owner's bulk delete only removes master templates. Category rename/delete changes shop medicines and their linked inventory categories through the authenticated Pharmacy API. On a fresh database, use the updated complete baseline instead.

For the **Supplier Return** page on an existing Supabase Pharmacy database, apply `059_pharmacy_supplier_return.sql` **after** `058_pharmacy_owner_catalog.sql`, then deploy the updated application. It adds invoice-line return ledgers and a transactional service-role RPC. Existing batch-linked return history is preserved. Fresh installations already include these tables and RPC in the complete baseline; do not replay this migration on top of that baseline.

For supplier returns of quarantined medicines on existing Supabase installations, apply `060_pharmacy_quarantine_supplier_return.sql` **after** `059_pharmacy_supplier_return.sql`. It adds a nullable quarantine link to the existing supplier-return lines and updates the atomic RPC so quarantined items are returned without removing saleable stock twice. The fresh complete baseline includes these changes.

### Mobile Scanner (Pharmacy only)
Apply `061_mobile_scanner.sql` **after** the Pharmacy Console/Product tables are installed and **before** deploying scanner API/PWA code. It creates temporary draft, pairing, binding and scan-event records plus two atomic queue/save-barrier functions; it does not migrate invoice or stock data. A fresh install using `ems_complete_schema.sql` or `baseline/001_ems_complete_schema.sql` includes these definitions already. Do not replay the additive migration on a fresh install. Scanner records expire; old drafts and their dependent records are pruned opportunistically when new drafts start.

For Scanner support on Electronics **sales and purchases**, apply `062_mobile_scanner_purchase_login.sql` after `061_mobile_scanner.sql`, then `063_scanner_electronics.sql` before deploying the matching code. This adds separate Electronics scan events and retry-safe invoice-save keys around the existing invoice RPC. It removes the retired `scanner_pairs` table. Fresh baselines already include the final definitions; do not apply these migrations again to a fresh baseline.

For per-shop ConnectX email sender and limit preferences, apply `064_connectx_shop_email_settings.sql` after migration 063 before deploying the updated ConnectX code. It is additive and does not modify the Owner sender or SMS settings. Fresh complete PostgreSQL schemas include it.

For curated App Store category, developer, featured state, web app link and screenshot URLs on **existing** PostgreSQL databases, apply `065_app_store_presentation.sql` after `064_connectx_shop_email_settings.sql` before enabling the new Owner metadata editor. Fresh complete baselines include the fields; existing APKs and download keys are unchanged.
