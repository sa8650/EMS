# Owner Pharmacy catalog and categories

## Install / upgrade

- Existing Supabase database: apply `supabase/migrations/057_pharmacy_catalog_details.sql` and `058_pharmacy_owner_catalog.sql` if not already applied, then apply **`supabase/migrations/059_pharmacy_supplier_return.sql`**. Do not rerun previously applied migrations.
- Existing Cloudflare D1 database: apply `supabase/d1/migration_pharmacy_catalog_details.sql` and `migration_pharmacy_owner_catalog.sql` if not already applied, then apply **`supabase/d1/migration_pharmacy_supplier_return.sql`**.
- Fresh installs: use the corresponding updated complete schema (`supabase/baseline/001_ems_complete_schema.sql` or `supabase/d1/001_ems_schema.sql`); **do not** replay incremental migrations on top of a fresh schema.
- Deploy the updated application code after the migration. No migration or deployment has been applied to a remote database by this delivery.

## Owner Console → Pharmacy Settings

**Medicine Catalog** is a global collection of **templates**, not a shared stock ledger. The Add/Edit medicine form uses the Pharmacy Console editor. Supplier and Rack / Shelf appear as shop-specific fields and cannot be assigned to a global template. Active templates are offered for import; inactive templates stay in the Owner catalog but are not offered for new imports. Individual and selected bulk deletion remove **only** master templates, never previously imported shop medicines. Selection stops at **200** templates; use Clear selection or uncheck items to choose another set. **Download actual catalog CSV** exports the current unfiltered master catalog, including inactive templates, saved units, IDs and timestamps; it is distinct from **Download CSV template**. The download fetches the latest catalog before exporting.

**Manufacturers** manages global names. They appear in every pharmacy's Manufacturer list and medicine form. Pharmacy shops cannot edit or delete a global name. A shop can still add its own private manufacturer, visible only to that shop. If the Owner renames or deletes a global manufacturer, existing shop medicines retain their saved manufacturer text; deleting a name unassigns it from Owner templates.

## Importing into a Pharmacy shop

Open **Pharmacy Console → Medicines → Marketplace catalog**. Use the checkboxes and **Select all shown** to choose several active Owner templates, then **Add selected** to copy them into the shop; use **Customize** to review a single template in the medicine form, or **+ Custom medicine** to start from a blank form. Existing shop medicines and repeated selections are screened for duplicate barcode or matching name + strength + dosage form + manufacturer + pack size before adding. The server checks again before each save, including custom additions. Bulk imports use a separate request per medicine to stay within Cloudflare Worker limits; progress remains visible during Pharmacy page navigation. The shop receives **independent records** with zero stock and automatically generated shop SKUs. Supplier and Rack / Shelf are shop-specific and can be assigned in the editor or after bulk import. Later edits or deletion of Owner templates do **not** modify existing shop medicines. Purchases and stock continue through the ordinary pharmacy workflows.

## CSV bulk upload (Owner Catalog)

Use **Download CSV template** on the Owner page. The `name` header is required. Columns supported by the sample are `name,generic_name,strength,dosage_form,manufacturer,category,pack_size,barcode,sku,base_unit,purchase_price,sale_price,wholesale_price,reorder_threshold,pack_unit,units_per_pack,pack_selling_price,active`. The base unit is always a conversion factor of 1; optional `pack_unit` + `units_per_pack` defines a second conversion. Add global manufacturers before referring to their names in CSV. A blank SKU is allowed for a master template; the shop generates a SKU on import. Before saving anything, the Owner Console checks the entire CSV against a fresh Owner catalog snapshot and checks repeated rows within the file. A row is a duplicate if it shares a SKU, barcode, or the same medicine name + strength + dosage form + manufacturer + pack size (case-insensitive). The confirmation shows how many rows will be skipped; only unique rows are uploaded. Concurrent duplicates are still protected by server checks and database SKU/barcode constraints. Upload at most 300 rows and 1 MB per file. The Owner Console sends 15 rows per Worker request to stay below Cloudflare's per-invocation subrequest limit. A persistent progress toast remains visible while you navigate other Owner Console pages; the upload continues in the open browser tab. If a request fails, use **Retry remaining rows** in the toast. Refreshing the same Owner session resumes from the last completed batch using stable row IDs. Closing the tab or leaving the site cannot guarantee continuous upload without a server-side queue. Invalid and duplicate rows are skipped and listed in the on-page import report.

## Medicine form options

The shared Owner/Pharmacy medicine editor includes additional dosage forms such as Topical Solution, Injection, Gel, Oral Solution, Powder for Suspension, Granules for Suspension, ophthalmic/otic/nasal preparations, sprays, patches, suppositories and more. Base stock unit and pack conversion choices now include drops, doses, puffs, sprays, patches, syringes, cartridges, packs, test strips, mL, mg, mcg and other medicine units. Existing custom values remain selectable when editing.

## Shop Settings → Category

Add, rename or delete medicine categories in **Pharmacy Console → Settings → Category**. Renaming updates every assigned medicine and its linked inventory item's category in the shop. Deleting moves all matching medicines to **Uncategorized** and clears the corresponding inventory category; it does not change stock or history. Other shops and Owner templates are unaffected. Empty and reserved `Uncategorized` names cannot be created as custom categories.

Run `npm ci && npm test` to verify the Pharmacy regression suite and D1 / PostgREST API paths.

## Pharmacy Console → Supplier Return and loading states

All Pharmacy Console routes now show loading skeletons while their page data is being fetched (including the native Pharmacy dashboard, medicines, POS, purchases, returns, alerts, stock movements and Supplier Return, plus shared business pages).

Open **Purchasing → Supplier Return**, enter a Pharmacy purchase invoice number, select its medicines and the base-stock-unit quantities to return, then review and confirm. The shop checks previous returns and current stock, records a retry-safe return with item-level audit history, decreases shop inventory and reduces outstanding purchase due by up to the return value. Any remaining value is recorded as a supplier refund or credit, according to the selected settlement method. Invoice-level discounts and taxes are included when valuing returned lines. Existing invoice and historical batch-linked return records remain available; the new ledger does not edit or delete the original purchase lines. Permission to view/add purchases governs the page and submission. The database transaction protects against duplicate submissions, over-returning and negative stock. A supplier refund/credit is a recorded settlement, **not** an automated transfer of money or an automatic application of unallocated supplier credit to a later invoice.

The Pharmacy purchase-history API now batches its invoice-line counts to avoid one database request per invoice; supplier display names use the current store scope. The Customer Return table markup was also corrected to prevent a misplaced closing container.

## Pharmacy supplier quarantine & analytics upgrade

On existing databases apply migrations **059** and **060** in that order (Supabase: `supabase/migrations/059_pharmacy_supplier_return.sql`, `060_pharmacy_quarantine_supplier_return.sql`; D1: `supabase/d1/migration_pharmacy_supplier_return.sql`, `migration_pharmacy_quarantine_supplier_return.sql`). Fresh installs use the updated complete schema. Do not replay additive migrations on a fresh schema. No remote database was migrated in this delivery.

**Quarantined Supplier Return:** Look up an original Pharmacy purchase and choose either saleable stock or a quarantined customer-return item of the *same medicine* for each purchase line. Quarantine quantities are verified and consumed separately, and are never deducted again from saleable stock. Both sources count toward the original purchase-line return limit. Partial quarantine returns update remaining quantities in the quarantine list and report. A supplier return still adjusts its original purchase due and records any remaining refund or supplier credit. It does not move money automatically.

**Pharmacy Reports tab:** Interactive date-scoped KPI cards, daily/weekly/monthly chart bars, previous-period comparison, stock/quarantine valuation, sales/purchases, profit and loss, low/out stock, legacy expiry, returns/exchanges, customer/supplier dues and payments, expenses, stock movements and best/least-selling medicines. Searchable sortable paginated tables support drill-down to saved invoice lines. CSV and actual `.xlsx` downloads include filtered report rows; **Save PDF** uses the browser print dialog's Save as PDF option, with print styles. No third-party charts or dummy transactions are used.

Sales COGS uses each saved sale-line cost snapshot, not today's medicine cost. Returned sellable units reverse their historic cost; damaged/quarantined units retain cost, and are valued outside saleable stock until a matching supplier return recovers their cost; that recovery offsets COGS without being treated as new sales. Invoice-level discounts/taxes are allocated to report lines. Due recovery is cash collection rather than a new sale; cash-flow totals subtract recoveries already included in updated invoice/expense paid balances before adding period collections. Quarantine valuation uses its original sale cost snapshot where available, otherwise the medicine's weighted-average cost. Stock value and outstanding dues are **current balances** even when a historical period is selected; transaction KPIs, charts and tables obey the date filter. The current aggregate-stock Pharmacy workflow does **not** store expiry information for new receipts, so the expiry view identifies **legacy batch records only**, never claiming to show all current expiring medicines. Exchange replacement historic cost is not saved by existing transactions, so exchange-period profit uses the medicine's current weighted-average cost as an estimate; it should not be treated as an exact historic exchange COGS. Other costs such as payroll/taxes count toward Net Profit only if recorded in Expenses, to avoid silently double-counting. Large date ranges may need narrowing to stay within Cloudflare's request budget.
